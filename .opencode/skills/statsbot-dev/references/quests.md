# Квесты (гео-квесты)

Мини-игра в Mini App: админ создаёт квест с чекпоинтами (координаты + вопрос),
участники доходят до точек, отвечают и завершают квест. Результаты — на отдельной
странице с двумя вкладками.

## Модель данных (`V17__quests.sql`)

| Таблица | Поля |
|---|---|
| `quest` | `id`, `title`, `description`, `active`, `created_by`, `created_at` |
| `quest_checkpoint` | `id`, `quest_id` (FK cascade), `sort_order`, `title`, `question`, `answer`, `lat`, `lon`, `radius_m`, `media_type`, `media_file` |
| `quest_participant` | `id`, `quest_id`, `user_id`, `started_at`, `finished_at` (уникально `quest_id+user_id`) |
| `quest_pass` | `id`, `participant_id`, `checkpoint_id`, `answer`, `passed_at` (уникально `participant_id+checkpoint_id`) |

Вложения чекпоинта — каталог `{upload-dir}/quest-{checkpointId}/`, отдаются через
`/images?id=quest-{id}&name={media_file}`. `media_type` — `image` или `audio`.

## Логика

- **Создание** — только супер-админ: `POST /app/quests/new` (название/описание), затем
  редактор `/app/quests/{id}/edit`.
- **Чекпоинты** добавляются по одному (`POST /app/quests/{id}/checkpoints`, multipart):
  вопрос, правильный ответ, координаты, радиус, вложение. Так проще, чем динамические
  массивы в multipart-форме.
- **Участие** — явная кнопка «Участвовать» (`POST /app/quests/{id}/join`): создаётся
  `quest_participant`, участник появляется на странице результатов.
- **Ответ** (`POST /app/quests/{id}/answer`): принимается, если пользователь участвует,
  чекпоинт ещё не пройден, он внутри `radius_m` от точки и ответ совпал
  (без учёта регистра, лишних пробелов, `ё` → `е`).
- Последний пройденный чекпоинт ставит `finished_at` — квест завершён.
- **Радиус появления** (`radius_m`, по умолчанию 50, максимум 5000) — расстояние,
  внутри которого чекпоинт «открывается»: показывается форма ответа.
  На карте у точки рисуется окружность радиуса.
- Координаты присылает клиент (`navigator.geolocation`); сервер пересчитывает расстояние
  по гаверсинусу. Подделать координаты технически можно — для квестов осознанно
  допустимо (см. `decisions.md`).

## Страницы

| URL | Шаблон | Доступ |
|---|---|---|
| `/app/quests` | `quests.html` | любой авторизованный: активные квесты + свой прогресс; супер-админ — все + создание |
| `/app/quests/{id}` | `quest.html` | участник: карта, чекпоинты, «Участвовать», формы ответов |
| `/app/quests/{id}/edit` | `quest-edit.html` | только супер-админ |
| `/app/quests/{id}/results` | `quest-results.html` | только супер-админ, вкладки «Участники» / «Завершившие» |

Пункт меню «Квесты» (`index.html`) виден всем — это пользовательская функция.

## Карта

Яндекс.Карты JavaScript API 2.1. Ключ — `yandex.maps.api-key` (env `YANDEX_MAPS_API_KEY`).
Если ключ пуст или скрипт не загрузился — страница показывает заглушку, а админ вводит
координаты руками (форма не блокируется). В редакторе клик по карте подставляет
широту/долготу в форму нового чекпоинта.

## Сервис и контроллер

- `service/QuestService` — создание, чекпоинты, `join`, `answer` (`AnswerResult`),
  `progress` (`QuestProgress`), `distanceMeters`, валидация радиуса/координат/медиа.
- `rest/QuestController` — страницы и действия. Права: `requireUser` (любой
  авторизованный, иначе bootstrap-страница) и `adminAuthGuard.allow(..., false)`
  (только супер-админ).
- `repo/QuestParticipantRepo.findParticipantViews` — native-проекция
  (`QuestParticipantView`) с именем из `users` и числом пройденных чекпоинтов.

## Проверка

- `QuestServiceTest` — расстояние, вступление, неверный ответ, слишком далеко,
  повторный ответ, завершение на последнем чекпоинте, вложения, прогресс.
- `TemplateRenderTest.rendersQuestPages` — рендер всех четырёх шаблонов.
- Миграция проверяется на одноразовом Postgres (см. `data-migrations.md`); отдельно
  полезно проверить каскады: удаление чекпоинта чистит `quest_pass`, удаление квеста —
  участников и чекпоинты.
